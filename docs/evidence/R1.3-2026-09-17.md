# R1.3 — shared form and state components, language on your own account, the phone baseline

Run on 2026-09-17 on branch `r1-3-shared-states`. Baseline `d3eca8e` (R1.2).
Verified against a production build on `localhost:3100` with the R0.2 fixtures.

## 1. B-05 and B-14 — a title is text somebody typed

`title_hi` and `title_en` were both `NOT NULL`, so a school that works in Hindi
typed every request title twice to buy a translation nobody asked for — and the
four screens that rendered it all did
`language === "en" ? titleEn : titleHi`, which is a **blank title** the moment
only one half exists. The two defects held each other up.

| Piece | What it does |
|---|---|
| Migration `20260917110132` | Both halves nullable, blanks normalised to null, and a check that at least one survives. A request with no title is a teacher opening a link that does not say what is being asked |
| `src/platform/i18n/authored.ts` | `readAuthored()` decides what a reader sees **and whether it fell back**; `requiredHalf()` / `optionalHalf()` decide which half a form asks for |
| `src/ui/authored-text.tsx` | One component for all four render sites, plus `authoredTitle()` for a `PageHeader` and `authoredPlain()` for a WhatsApp body |
| `requestInputSchema` | One title required, in either language, with the error reported against a field the form renders |

The fallback is visible, not silent: a Hindi reader shown an English title sees
a small "in English" beside it. Hiding that is how somebody concludes the app is
half-translated and stops trusting the rest of it.

Verified in the browser as the office (Hindi): the form asks for **हिन्दी**
(required) and offers **नाम / English** (optional).

## 2. B-06 — school order, on four screens

`"Class 10".localeCompare("Class 2")` is negative, so every screen that sorted
class labels as text listed Class 1, Class 10, Class 11, Class 12, Class 2. A
teacher looking for Class 2 found it ninth.

The order already existed and was being thrown away: `public.classes.sort_order`
and `vppsone.class_aliases.sort_order`. `classLabelMap()` is now built in school
order — a Map keeps its insertion order — so three screens simply stopped
sorting, and the fourth (a teacher's own classes, a subset) ranks against it
with `rankOf()`.

`tests/class-order.test.ts` scans every source file for the two shapes that
caused it, so a fifth screen cannot reintroduce it.

**Correction to the R0.1 record:** this was **four** screens, not five.
`/timetable/page.tsx:90` sorts *staff names* alphabetically, which is correct.

Verified in the browser: the class picker reads NUR, JKG, SKG, Class 1,
Class 2, Class 3…

## 3. Self-service language (PLAN §3a)

`/preferences`, guarded on being staff and nothing more. It writes one column on
the row belonging to whoever is asking, found by their own `user_id` — there is
no id in the form to tamper with, and changing your own language cannot grant
you anything.

Each option is written **in its own language** (हिन्दी / English /
हिन्दी + English), because somebody who has ended up on a screen they cannot
read needs to recognise the word for their own language.

Reached from the top bar beside sign-out, not from the thumb bar or More: both
are about the person rather than the school, a teacher's bar is already full so
More is not a tab she has, and this is the one setting somebody may need
*because* they cannot read the screen they are on.

Verified end to end in the browser: the QA office account switched Hindi →
English (the whole shell re-rendered, nav read Home · Collect · Apps · Teach ·
More) and back to Hindi, with the database confirming both writes.

## 4. B-23 — named landmarks

`Section` rendered a bare `<section>` with an `<h2>` inside, so every landmark
on every screen announced as "region" and nothing else. It now carries
`aria-labelledby` pointing at its own heading, with the id derived from the
English half so it is stable whoever is reading.

`Field` gained a `hint` slot for a sentence above the control — "one language is
enough", "optional" — rather than below it, where it is read after somebody has
already typed the wrong thing.

## 5. The phone baseline, and the bug it found

`tests/e2e/responsive-baseline.spec.ts`: six screens × 360/390/430px, checking
the two things that make a screen unusable rather than untidy — no page-level
horizontal scroll (QA.md: "Page-level horizontal overflow fails"), and no
primary target under 44px.

**18 of 18 pass.** The first run did not:

```
/teach/attendance has controls under 44px tall at 360px
  + "← मेरा दिन (20px)"
```

The `PageHeader` back link was a 20px inline link — the smallest target in the
app, on the screen a teacher opens most, reached with a thumb while holding a
register. It is now 44px tall with the text still at 13px, and a negative margin
keeps the extra height from moving the title.

The first version of the check also failed the forms, and that was the *check*
being wrong: a checkbox is drawn 20px inside a 48px row that is the real target.
It measures the label now.

### A fixture bug worth recording

Eighteen cases signing in individually asked Supabase for eighteen one-time
links in a minute and got rate-limited — which surfaced as "sign-in bounced to
/login" on the cases that happened to run last, and reads exactly like a
permission bug. `sessionCookies()` mints one session per account and hands it to
each page. Tests that are *about* signing in still call `signIn()`, because
reusing a session would not test the door.

## 7. Limitations

- The authored-text pattern is applied to request **titles** only. Reasons
  (`reason_hi` / `reason_en`) still have no Hindi field on the form — the hidden
  empty input B-14 named is gone from the render path, but the *form* half is
  R3.2's, where the request wizard is rebuilt.
- `/preferences` holds one setting. Notification and display preferences are not
  in scope for any current row.
- The responsive baseline is six screens, not the full matrix, and checks two
  rules. No axe pass, no keyboard walk, no 200 % zoom, no landscape, no
  768×1024 — all R7.2.
- The 44px rule is checked on *height* only. Width is rarely the failing
  dimension in a single-column phone layout, but it is unchecked.
- `Section`'s landmark id comes from the English half of its title. Two sections
  on one screen with the same English title would collide; none do today, and
  nothing yet asserts they cannot.
