# R2.1 — the teacher's day, with one thing to do next

Run on 2026-09-17 on branch `r2-1-teacher-today`. Baseline `3aa251f` (R1.3).
Verified against a production build on `localhost:3100` with the R0.2 fixtures.

The visual reference is the design package another agent left at `docs/design/`
(`teacher-mobile.png`, `SCREENS.md`, `HANDOFF.md` D2). It is untracked and not
committed here, by the user's decision; its layout is followed and its
conflict order respected — where a card it shows would need data this app does
not have, the card is **not rendered** rather than filled in.

## 1. B-20 closed — eight lessons, not twenty

The Today card listed one row per timetable slot. A subject taught to five
classes at once — ELGA, games, assembly — is five slots, so period 3 rendered
as five lines and a teacher saw **20 entries for an eight-period day**, being
told she was in five rooms at once.

`lessonsToday()` groups by period **and subject**, so a combined lesson is one
row carrying its classes. Two *different* subjects in one period stay two rows:
that is a clash, and merging it would hide the thing worth seeing.

Verified in the browser, the QA teacher's real Thursday:

```
1  Class 2                                          Maths
2  Class 2                                          Maths
3  Class 1 · Class 2 · Class 3 · Class 4 · Class 5  ELGA · एक साथ
4  Class 1 · Class 2 · Class 3 · Class 4 · Class 5  ELGA · एक साथ
5  Class 1 · Class 2 · Class 3 · Class 4 · Class 5  ELGA · एक साथ
6  Class 3                                          Maths
7  Class 1                                          EVS
8  Class 1                                          EVS
```

A combined lesson gets **no** open-class link: offering one of the five would
be picking a room at random.

## 2. One prominent next action (PLAN §1)

`nextAction()` returns the first outstanding register, or nothing with a reason.
`TaskHero` renders it as the only accent-coloured block on the screen, so "what
do I do now" is answered by colour before it is answered by reading.

Verified as the QA teacher:

> **सबसे पहले** — हाज़िरी ले लीजिए
> Class 1 में 15 बच्चे — हाज़िरी बाकी है।
> [ हाज़िरी लें → ]

The count is one `classRoll` read, for one class, only when there is a register
to take. "15 children in Class 1" is what makes the action concrete; a figure
nobody can act on is not worth a query on the screen a teacher opens at 7:40.

**When everything is in, there is no hero at all.** No fallback action is
invented to fill the space — "you are finished" is the most useful thing the
screen can say, and a made-up task is how it stops being believed.

## 3. Metric cards, and the ones that are not there

| Card | Shown | Source |
|---|---|---|
| मेरी कक्षाएँ | count of classes held, or **—** | `class_teachers` |
| आज के पीरियड | merged lesson count, or **—** when nothing is published | published timetable |
| आज की व्यवस्था | cover duties, warning tone, only when > 0 | published cover plan |
| जाँचने को | pending corrections, only with `attendance:correct` | corrections queue |

**A dash, not a nought**, when the timetable is not published: "there is no
timetable" and "you have a free day" are different news and a 0 tells the wrong
one.

The design's `teacher-mobile.png` also shows **Open requests** and **Records to
check**. Neither is rendered: a teacher's request inbox is R3.3 and does not
exist, and records are `collection:view` which a teacher does not hold. The
package's own acceptance forbids invented counts, so the cards are absent
rather than zero.

**Also not rendered: lesson times.** The design shows 08:30 / 09:10. There is no
bell schedule in this database — Phase 4.1 deliberately dropped the source
repo's `DEFAULT_SHIFTS` (D-61) — so periods are numbered, not timed. Recorded as
a deviation rather than filled with plausible times.

## 5. A bug this task created, and the fix that removes the class of it

`classRoll(classId, sessionLabel)` — two strings in a row. I passed them the
other way round, TypeScript said nothing, and the teacher's screen rendered
the error card with `invalid input syntax for type uuid: "TEST-2026-27"`.

The message was clear; the signature was the problem. `classRoll` takes a named
object now, across all seven call sites. One brace, and the mistake becomes
unrepresentable.

## 7. Limitations

- **Marks due is not on the card.** A teacher's outstanding marks need the
  assessment papers for her classes and their completeness; that read belongs
  with R5.3's marks work rather than being bolted onto Today for one number.
- No "next lesson" claim, for the reason above: without bell times the app
  cannot say which period is now.
- A teacher holding **more than one** class gets one hero for the first
  outstanding register and the rest in the list below. The design's own-class
  selector for a multi-class teacher is not built; no QA account holds two
  classes today, so it is also untested.
- Nothing here is covered by a browser journey of its own. The existing teacher
  journey exercises the register and the "needs doing" list, and passes, but the
  hero and the metric cards are verified by screenshot rather than by assertion.
- The other five role homes are still the profile card plus links. R2.2.
