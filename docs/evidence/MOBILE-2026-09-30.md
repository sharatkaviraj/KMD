# Mobile workspace refresh — 30 September 2026

## Scope and design

Source baseline: `67bb5c47f80a4ea1f0aa0bcbf93fcc1987dfbf2c`, branch `main`.
The user requested mobile UI, accessibility and performance improvements,
commit/push to main and application-code production deployment. After reviewing
the design preview, they requested balanced centering/symmetry and polished
animations. This release keeps the current backend and financial policy.

- Branded, centered sign-in card; retained entered email and linked/focused errors
- Bounded centered mobile workspaces, consistent gutters and aligned task cards
- Larger readable record labels/values with wrapping names and reasons
- Phone inputs/selects/tabs/icon actions at least 44px in the shared recipes
- Role-correct More destinations and tablet navigation, including native modules;
  universal personal preferences and the actual native role name
- Named sheets with description association, visible keyboard focus, Tab loop,
  Escape, focus return, nested-modal inert ownership and main-scroller locking
- Localized session picker with visible selected, loading, error and retry states
- Measured bottom-bar clearance so wrapping labels do not cover the last record
- Restrained screen fade/panel entrance and button feedback; reduced-motion opt-out
- Skip-to-content and best-effort scroll restoration when session storage is blocked

No authentication guards, money allocation/idempotency, offline attendance
payloads, WhatsApp/PWA decisions, schema or deployment environment variables
were changed. `schoolfees` live is not a target of this work.

## Performance evidence and limits

The clean baseline production build passed before edits (Node 24.19.0, installed
Next 16.3.5, webpack). The baseline emitted 79 JS chunks totaling 2,794,082 raw
bytes / 833,572 gzip bytes, measured by the same local zlib recipe. These totals
cover **all** routes; they are not a phone's initial transfer size or Core Web Vitals.

Two concrete workload reductions are regression-tested:

1. Native roles without `fees:view` no longer start the shell's financial summary
   and receipt-policy reads. Authorized fee roles retain both reads. This avoids
   optional fee query work on teacher/coordinator/viewer screens; no query latency
   percentage is inferred.
2. Background route warming skips offline, hidden, Save-Data and 2G states,
   deduplicates destinations and avoids rewarming the same route inside 60 seconds.

The session picker also keeps a stable empty-session list rather than an array
literal that could restart its list-read effect on each render. New animation
keyframes affect opacity/transform only; the screen fade deliberately has no
transform so fixed payment CTAs retain their viewport containing block.

No authenticated before/after network trace, Lighthouse score, p75 LCP/INP/CLS,
physical Android/camera/printing measurement or staff timing trial was obtained.
