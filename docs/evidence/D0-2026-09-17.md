|---|---|
| `teacher`, `teacher-hi` | `teacher`, with `preferred_language` deciding the second |
| `admin` | `admin` |

| `viewer` | `view_only` |
| `accountant` | **No VPPS One role.** School Fees' own identity model |

`?role=` in the atlas is a preview switch and has no equivalent here; nothing in
this branch reads a role from a query string, an email address or a menu label.

## Deliberate deviations from the atlas

1. **No `accountant` role, and none inferred.** The atlas's accountant home is
   the fee app's screen and belongs in the fee app. VPPS One implements the
   *landing*: `staff_profiles.preferred_start`, chosen by the person, resolved
   against `allowedFor(role)` and the app registry, ignored when the role no
   longer qualifies. It grants nothing — the fee app decides access on arrival.
2. **"First lesson", not "Next: English · 09:10".** `timetable_slots` holds a
   period index and no clock time, so nothing in this database knows what time
   it is in the school day. The card names the day's first lesson and its
   period number instead of inventing a time.
3. **Illustrative figures are not implemented as figures.** "94.2% present",
   "₹48,500 collected", "86% requests complete" are the atlas's fictional
   school. The implemented panel shows what dev actually holds, and shows a
   dash with a reason where a read fails.
4. **The shell keeps its centred container.** The atlas draws a sidebar flush
   to the viewport edge; this widens the existing centred `max-w-5xl` to
   `max-w-7xl` instead of restructuring the shell. Hierarchy and density match;
   the chrome's left edge does not.
5. **Groups keep PLAN §3's names.** The atlas's sidebar leads with the role
   ("ADMINISTRATOR", "CLASS TEACHER · VI A"); the sidebar here keeps
   Today's work / Records / Setup and the identity moved to the top bar.

## Defects found during this pass

- **B-38 — an issued link carrying a query string 404ed.** `/auth/confirm` set
  `url.pathname = sanitizeRedirectPath(...)`, and `URL.pathname`
  percent-encodes a `?`: `/teach/attendance?class=…` became
  `/teach/attendance%3Fclass=…`. Every magic link with a deep link that had
  query parameters was affected. Fixed, with an e2e assertion.
- **B-39 — `/\evil.example` passed the redirect check.** `sanitizeRedirectPath`
  refused `//host` but not `/\host`, which URL parsing for http(s) treats the
  same way. It happened not to be exploitable because the one caller assigned
  it to `URL.pathname`; fixing B-38 would have made it exploitable. Both are
  fixed in `isSafeInternalPath()`, with the newline/control-character case.
