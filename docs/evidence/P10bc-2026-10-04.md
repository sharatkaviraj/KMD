# P10b and P10c — SamPark's records in, by ids; children's photographs

Branch `p10-sampark-import-photos`, on main `f3bb72e` (P10a). Target:
schoolfees-dev (`wtgxcptmucjerhufzjcf`) only. Synthetic SamPark ids
(`QA-SP-…`, `QA-SPE-…`), synthetic `qa_` fields, synthetic 1×1 images.
Children are referred to by id. Nothing reads SamPark's database.

## P10b — bringing SamPark's records in (D-235)

At `/collection/import`, the office uploads SamPark's Students workbook. The
headers it reads are the ones SamPark's `student-export.ts` writes. Each row
resolves **by ids alone**:

1. an earlier mapping (`external_student_ids`, app `sampark`);
2. the SR number against the fee record's `admission_no`, leading zeros kept;
3. failing an SR, SamPark's admission number.

A name or phone never decides a row.

- **Ambiguous** rows are a number two children share, ids that point at
  different children, or two rows for one child.
- **Unmatched** rows have no usable id.
- Staging writes nothing to any child's record, and the same file again
  resumes its batch.
- Cells that do not validate are listed and not written.
- Every column the import does not read is named on the screen.

**Applying the matched rows** is one replayable command, `apply_sampark_import`:

- it records the mapping, which is what lets SamPark's own links name the
  child;
- it offers each value to the one writer (P10a) as an import from SamPark;
- precedence keeps any value a person recorded, and keeps another import's
  value;
- a mapping that disagrees with an earlier one goes back to the queue with
  both children named.

**The queue** is `resolve_sampark_row`. A person picks a candidate, or a child
by the fee record's SR number (`matched_on = hand`), or sets the row aside
with a reason. A decided row is not decided again.

## P10c — children's photographs (D-236)

`/collection/photos` shows a class at a time, the children without a
photograph first, with a missing count. A photograph comes from the camera, a
single file, or a folder.

**Folder placement** is ported from SamPark's `photo-filename.ts` without its
name tier:

- an id or SR number in the filename places the file;
- an id the filename split in two is recovered;
- two files for one child are both refused;
- anything else waits in a tray for a person to choose.

Placement proceeds one file at a time, with progress, after the photograph is
shrunk on the device to 800 px.

**Storage:** photographs are kept in the private `vppsone-photos` bucket and
reached only through signed URLs minted after a permission check.

**`place_student_photo`** is replayable, keeps one current photograph per
child, and keeps the replaced one, row and bytes. A placement that did not see
the current photograph is refused as `stale`. The fee app's `photo_path` is
not touched.

## P10d — workbooks (D-237)

`/collection/export/students` returns one row per enrolled child with each
collected value, a Sources sheet showing where each came from, and an About
sheet with the counts. `/collection/rounds/[id]/export` gives one sheet per
link: what each teacher was shown, her answer and its status. Both:

- are office-only and logged in `academic_exports` (kinds `students` and
  `round`, migration `20261004123341`);
- write every cell as text with the `@` format;
- clean sheet names as SamPark's `safeSheetName` and `uniqueSheetName` do.
