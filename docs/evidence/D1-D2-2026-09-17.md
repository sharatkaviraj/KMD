# D1–D2 — role homes, and where an account starts

17 September 2026. Branch `d1-d2-role-homes`, from `main` at `799babf`.
Read `D0-2026-09-17.md` first: it records what the atlas asked for, what was
already built, and the five deliberate deviations. This file records what was
built and what was actually checked.

## The three requirements, and how each is met

### 1. Accounts staff open the School Fees workspace

**Not a role.** `accountant` is the fee app's identity model and nothing in
this repository can grant it (CLAUDE.md rule 2, PLAN §3, D-6), so the
mechanism is an explicit start-screen preference the person chooses about
themselves:

- `vppsone.staff_profiles.preferred_start` — `NULL` for the role's Home, a
  VPPS One path, or `app:<registry id>`;
- `src/platform/config/start.ts` offers only what `allowedFor(role)` and
  `appsFor(role)` already allow, so choosing School Fees opens a door that was
  already on the Apps hub;
- the stored value is re-resolved on every read, so a role change takes the
  landing away with the permission rather than leaving somebody bouncing into
  `/access-denied` every morning;
- the server action re-checks the posted value against the same function, so a
  value typed into the form by hand is refused rather than stored.

Nothing reads a role from an email address, a menu label or a query string.

**Observed.** With `preferred_start = 'app:schoolfees'` on the QA office
account, a fresh magic link answers:

```
HTTP/1.1 307 Temporary Redirect
location: https://vpps-one.vercel.app/protected/dashboard
```

That hostname is the registry's verified fee origin (R0.1, B-15) — not a
guess, and not `schoolfees.vercel.app`, which is a different company's
product. The redirect is *read* rather than followed in the test: the
destination is the school's live fee app and a suite has no business loading a
production page to prove where a header points.

### 2. A teacher opens her own class and day

`/teach` was already the teacher's Home (R1.2). What it now says:

| | Before | After |
|---|---|---|
| Above the title | — | the weekday and date |
| Under the title | "Thursday, 17 September" | **"Your class · Class 1"**, or the list when she holds several, or "No class is assigned to you" |
| First metric | "My classes · 5" | **"Your class · 15"** — the children on the roll, linking to the class |
| Second metric detail | — | "First lesson: Maths · Period 1" |
| Today's periods | a fourth section down the page | a **supporting column beside the work** from 1024px, with a link to the full week |

The first metric reads the roll only when she holds exactly one class; a
teacher who holds several gets the count of classes, because five roll queries
to render one card is what R7.1 comes back to delete.

**"First lesson", not "Next lesson".** `timetable_slots` holds a period index
and no clock time, so nothing in this database knows what time it is in the
school day. The atlas's "Next: English · 09:10" is a design example; inventing
a time would be inventing a fact. Recorded as deviation 2 in D0.

### 3. An administrator opens the combined school overview

`/dashboard` for `admin` is now the overview the atlas asks for: exceptions
first, supporting figures beside them.

- **Needs attention** — unchanged (R2.2). Counts with owners.
- **Today at school** — attendance submitted, staff present, cover arranged,
  exams open for marks. Each a fraction with a small labelled bar, from
  `schoolOverview()`.
- **Information round** — the newest open round and how far it has got.
- **Fee collection** — **unavailable, with a next step, never ₹0.**
- **School workspaces** — the two sibling apps as desks, with their own
  environment label and hostname.

The profile card is gone from the administrator's home: the question it
answered is now in the top bar, and a screen about the school should not open
with a card about the person reading it. Every other role keeps it.

**Unavailable is not nought.** Every count in `OverviewFacts` is
`number | null`; a failed read renders a dash, says the count could not be
read, and draws no bar. `tests/overview.test.ts` asserts all four rows for
this, asserts that no published plan reads differently from an empty one, and
asserts that no rupee symbol can appear in the fee summary.

## Defects found and fixed

**B-38 — an issued link carrying a query string 404ed.** `/auth/confirm` did
`url.pathname = sanitizeRedirectPath(next)`, and the `URL.pathname` setter
percent-encodes a `?`:

```
old behaviour -> /teach/attendance%3Fclass=abc&day=2026-09-17
```

…and `url.search = ""` threw the query away as well. Every magic link whose
deep link carried parameters — which is every link into a register, a class or
a filtered directory — landed on a path that does not exist. Path and query are
now set separately. Observed fixed:

```
location: http://localhost:3100/teach/attendance?class=abc&day=2026-09-17
```

**B-39 — `/\evil.example` passed the redirect check.**
`sanitizeRedirectPath` refused `//host` but not `/\host`, which URL parsing
for http(s) treats identically. It was not exploitable only because the single
caller assigned it to `URL.pathname`, which encoded it — so fixing B-38 would
have turned it into an open redirect on the sign-in door. `isSafeInternalPath()`
now refuses a backslash anywhere and any control character, and
`tests/env.test.ts` covers both plus a header-splitting newline.

**B-40 and B-41 — the flaky suite had one cause, and it was not the timeout.**

The symptom first: `fan-out.spec.ts` measured **58.2 s against the suite's 60 s
default**, so the same build passed and failed on consecutive runs and the
failure read like a regression in whatever had been merged that day. Confirmed
pre-existing by running that spec against `main`, where it also took 58.2 s.
The ceiling went up to 120 s.

Raising it did not fix the run. `collection-freeze.spec.ts` then failed —
a *different* journey, on a page this branch does not touch. Its assertion is
that a request it just created appears on `/collection`, and the accessibility
snapshot in the failure report showed that list full of titles hours old.

**B-41 is the cause.** Three specs ended with `delete from collection_rounds`
under a comment claiming it cascaded to the round's links. It does not:
`collection_requests.round_id` is `ON DELETE SET NULL`, which is the right rule
for the app — archiving a round must not destroy answers a teacher already sent
— and the wrong assumption for a teardown. So every fan-out run left **three
live requests** behind on a database three journeys share. `listRequests()`
reads them all with a query per row, so every journey touching `/collection`
had been getting slower for a fortnight, and one of them eventually failed
outright rather than merely dragging.

`removeRound()` in the harness deletes the links first — those cascades are
real — and all three specs use it. Thirty-four leftovers were removed from
schoolfees-dev, leaving only the seeded fixture request.

The measurements either side:

| | Before | After |
|---|---|---|
| `npm run smoke:workflows` | 12.4 min, 1 failed | **1.8 min, 42 of 42** |
| `fan-out.spec.ts` | 58.2 s | 10.6 s |
| `collection-freeze.spec.ts` | failed at 15 s | 10.1 s |
| Live `collection_requests` rows on dev | 35 | 1 |

The raised ceiling stays on that one journey, which is still the longest; the
suite default is left alone, because it is what would catch the next test that
starts taking a minute — the signal that was nearly lost this time.

## Evidence gaps — named, not worked around

- **The populated information-round card was not observed against real data.**
  The only round on dev is a draft over a class with no class teacher, so no
  link can be minted for it (the same condition R3.3 demonstrates as "blocked").
  The empty and unavailable states were observed; the populated one is covered
  by unit tests of the shape only.
- **The fee destination was not opened.** The redirect target is asserted from
  the `Location` header. Opening it would be loading the school's live fee app,
  which R6.2 already records as needing a staff-reachable test origin (B-16).
- **Not a physical-device pass.** Emulated widths in Chromium. Android,
  webview, software keyboard and print remain R8.3's.
- **Not the full D4 state matrix.** Expired sessions, two-tab conflicts,
  provider failures and 200% zoom belong with R7.2 and R8.1; this branch
  checked the states its own screens can be in.
