# P10a — Collected values: one writer, kept history, precedence in the database

Branch `p10-record-precedence`, on main `cca20a6` (P9). Target: schoolfees-dev
(`wtgxcptmucjerhufzjcf`) only. A synthetic, inactive `qa_` field, synthetic
links and synthetic numbers in the `98000…` and `98123…` blocks. Children are
referred to by id only.

P10 is SamPark's residual parity. This is its first part: the overlay that
collected values land in now has one writer, a provenance for every write and
precedence enforced in the database. The import with its identity queue
(P10b), photographs (P10c) and workbooks (P10d) are built on top of it.

## What changed

**One writer.** `vppsone.write_student_value()` is the only function that
writes `student_records`, and only the database's own commands can call it.
Every write it makes, and every value it refuses, goes into
`student_record_history` with:

- old and new value;
- old and new source;
- the import's name;
- the submission or file row it came from;
- the command, the actor and the time.

The history is append-only. The one exception is a synthetic `qa_` field,
which the tests create and remove. An architecture test fails the build if
anything in `src/` writes `student_records` directly. The one value already
held on dev was given a `held_before_history` row.

**Deciding answers is one command, `accept_submissions`.** It runs in one
transaction:

- the actor still holds `collection:manage`;
- only answers still pending are decided, so whoever comes second is told
  somebody else got there first;
- a repeated command id returns its first receipt;
- the ids travel in the request body, so accepting four hundred confirmations
  is one call.

Two cases are refused by name instead of decided by accident:

- **`superseded`**: a newer answer for the same child and field is waiting.
  The review screen offers only Reject on that row.
- **`record_moved`**: the value changed after the teacher was shown it. The
  row offers **Accept and replace the newer value** instead of Accept, and
  only that choice replaces it.

The receipt names every count and every refusal.

**Precedence**, ported from SamPark's `precedence.ts`:

- A teacher's or the office's value is never replaced by an import.
- An import may correct only what the same import wrote.
- What precedence refuses is kept as `blocked`, with the reason.
- The same value, confirmed by a person over an import's, becomes a person's.

**The child's card** now has "How these values changed": what each change
replaced, from which source, by whom and when, and what was refused.

`verify:records` (19):

- **Authority:** a teacher cannot decide.
- **Accepting:** it writes the teacher's value naming the answer, and keeps it
  in the history.
- **Replay:** a repeated command does nothing, and a reused id for a different
  decision is refused.
- **Already decided:** deciding an answer someone else already decided changes
  nothing.
- **Superseded:** an older answer is refused and stays pending, and the newer
  one is accepted.
- **Record moved:** the answer is refused by name, and is replaced only with
  `replace_newer`, with the old value kept.
- **Blank or unchanged:** a blank answer and the value already held are
  confirmations; a rejection writes nothing.
- **Bulk:** 400 ids are one call.
- **Race:** of two people deciding at once, one decides, the other is told,
  and there is one write.
- **Atomicity:** an injected fault after the first write leaves nothing
  written or decided.
- **Append-only:** history cannot be edited or deleted.
- **Cleanup:** the synthetic field leaves nothing behind.

## Not established

- **The import side of precedence is not exercised here.** No importer
  exists until P10b, and `write_student_value` cannot be called directly. The
  `human_value` and `other_source` refusals are first driven by P10b's import
  command and its verifier.
- An office member still cannot edit a value directly on the child's card. The
  `office` source exists for that, but no screen writes it.
