# P9 — Parent message policy: approval by default, stale approval blocked

Branch `p9-parent-policy`, on main `c3dfd64` (P8). Target: schoolfees-dev
(`wtgxcptmucjerhufzjcf`) only. Synthetic numbers in the unroutable `90000…`
and `99999…` blocks; nothing is sent to anybody. Opening WhatsApp is a link
the tests never follow, and the app's own parent dispatch stays off.

## What changed

**The policy is per category, and approval is the default.**
`parent_message_policies` has four categories:

- asking for details or documents;
- sending a report card;
- an absence notice;
- anything else.

Every category starts out needing a person's approval. A category can stop
needing approval only with a bounded exception that names four things:

- who it goes to;
- what triggers it;
- what it may say;
- what happens when it needs correcting.

A database constraint enforces that, so a blank counts as missing. Any change
moves the category's version. A second save racing the first is refused and
the first one stands; it is never applied on top. Administrators edit the
policy at `/collection/policy`, and the office reads it there.

**The app dispatches to a parent only when three things hold together.** The
school's `parent_dispatch` switch is on, the category names an exception, and
nothing about the message is stale (`mayDispatchToParent()`). Otherwise D-10
holds and a person sends it from their own WhatsApp. On dev, and at release,
the switch is off and every category needs approval.

**An approval rests on a snapshot.** Queueing a parent message pins:

- where it is going;
- the guardian number on the child's record;
- the version of what it is about;
- a hash of its text;
- the policy version.

"Approve and open WhatsApp" compares that snapshot with today's values. If
anything differs it refuses and names every difference; otherwise it records
the approval and gives the link. "I sent it" compares again.

**A send that happened is kept.** If something changed between approving and
sending, the send is still recorded and the screen says a correction is owed.
The reasons are written on the row before it becomes `sent`, because a sent row
is never rewritten afterwards. The screen reads them from the row, so they are
still there after a reload.

**A wrong number is a flag.** Anyone who works the messages can report a
parent number as wrong, saying why. When they do:

- every unsent message to that number is withdrawn, with the reason, and each
  withdrawn row says so in the reader's language;
- a sent message to it is untouched;
- the number is listed at the top of the messages screen;
- a new parent message to it is refused when someone tries to queue it.

An administrator clears the flag with a note, and the flag is kept. Office
staff can read flags; teachers cannot.

## Migration

`20261004084641_parent_message_policy` (`vppsone`, additive, applied to dev):

- `parent_message_policies`, with its named-exception check and four seeded
  categories;
- `message_sends` gains `category`, `approved_by`, `approved_at`, `snapshot`,
  `stale_at` and `stale_reason`;
- `parent_route_flags`, with its must-say-why and cleared-by-somebody checks,
  read under `collection:view`.

It reuses the existing `runtime_flags.parent_dispatch`, which is off.

## Not established

- **The school's own policy.** Nobody at the school has chosen a category
  for automatic sending, and none is set. Until somebody does, every parent
  message is sent by a person.
- **Report card and absence-notice messages are not queued anywhere yet.**
  Their categories exist so the policy can be set before they are built. A
  queued message is `collection_request` when it answers a request and
  `general` otherwise.
- **No provider was exercised for a parent.** The switch is off and no
  exception exists, so the automatic path is proved only by the pure rule and
  the database checks, never by a send. A real send to a parent stays behind
  rule 8 (stop and ask).
- A message queued before this migration has no snapshot. Approving it asks
  for a fresh look (`record_changed`); it is not grandfathered in.
