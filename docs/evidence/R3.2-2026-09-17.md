# R3.2 — see who a round reaches before you make it

Run on 2026-09-17 on branch `r3-2-round-wizard`. Baseline `652393c` (R3.1).
Verified against a production build with the R0.2 fixtures on schoolfees-dev.

## 1. What this closes

R3.1 gave a round a table and no way to make one. This is the screen: choose an
audience, see the real count, and write the round down. It does **not** mint
links — that is the fan-out, in R3.3.

The office almost never wants a whole class. It wants the nine children whose
phone number is blank, and before this, seeing those nine meant asking nineteen
teachers about five hundred — which is how a gap survives three rounds of
asking (S-03).

## 2. The count is the whole screen

`/collection/rounds/new` is **two forms on one page**. The top one is a `GET`
that only changes the URL; the bottom one is the `POST` that creates the round,
carrying the same selection as hidden fields.

So the number the office reads is a **server render of the real resolver**, not
arithmetic the browser did on what it happened to have loaded. The day those
are two code paths is the day a preview says nine and the round covers eleven.

It also means the screen ships no JavaScript of its own. Ticking a class is a
page load — slower than a click, and it works on the connection this is
actually opened on, with Back and a shareable URL thrown in (D-139).

| | |
|---|---|
| `resolveAudience()` | One resolver, used by the preview, the round page and (in R3.3) the fan-out |
| Enrolment first | Not `public.students.class_id`, which holds where a child is *today* and is overwritten on promotion |
| Paged | `fetchAllRows` throughout: PostgREST truncates at 1000 with no error (D-62) |
| Chunked `in()` | On the input as well as the output — a 500-id `in()` is a URL refused before rows are ever counted |

## 3. The audience model, ported rather than invented

The R3.1 branch already corrected the shape after reading SamPark's own
`students.ts` (rule 4). Two rules from it are load-bearing here:

- **OR within a dimension, AND across them.** "Classes 6 to 8, Rana Pratap
  house" is those three classes *and* that house.
- **A missing filter must never widen the blast radius.** An audience with
  nothing set selects **nobody**; `allEnrolled` is the deliberate "everybody".

The URL parser follows the same rule in the one direction that is safe: a value
it cannot read is dropped, and dropping narrows. A hand-edited URL cannot widen
a send — including the case where a leftover `all=1` meets a ticked class, where
the class wins.

## 4. Gap filters

`gaps.ts` is what "missing" means, in one place, so the preview count and the
round cannot come to disagree about it.

- **Blank is missing; wrong is not.** A nine-digit phone number is a different
  problem from no phone number, and rolling them together puts a child the
  office must fix itself onto a teacher's list with nothing to tell her which
  she is looking at.
- **Two gaps mean *both*.** "No phone and no date of birth" is the smaller set.
  Reading it as "any" would send to more children than were picked — so
  `describeGaps()` says "and", never "or". Getting that backwards is not a
  wording slip; it is a teacher told she is being asked about different
  children than she is.
- VPPS One's own accepted answer beats the fee column, the same precedence the
  link and the review queue use.

The suggested reason is derived from the filters actually chosen, so a narrowed
round arrives with a sentence already in the box rather than an empty required
field and a shrug.

## 5. The ask list

For the case no filter can find: thirty-five families whose number is on record
and is not a WhatsApp number. Nothing about those children is missing, so no
query finds them and the office is the only thing that knows (S-06).

Ported from SamPark `ask-list.ts` with one change — it reads **CSV**, not
`.xlsx`. `SOURCES.md` records that `excel.ts` was not ported: a spreadsheet
library to parse a file Excel already exports is a dependency bought for
nothing. The BOM and CRLF are the part that was kept, because without them
Excel opens the Hindi notes column as mojibake.

**What did not match is the point.** A list of six that quietly becomes a round
of three is the worst thing this can do. So the upload is two steps and the
first creates nothing: every non-blank row comes back either matched or named,
by the row number Excel shows down the left.

Exercised in the browser with a sheet broken three ways at once:

| Row | What it was | What came back |
|---|---|---|
| 2, 3 | two real SR numbers with notes | matched, notes carried |
| 4 | `NOPE-404` | "No one child has this SR number" |
| 5 | a name and no SR | "A name alone cannot identify a child" |
| 6 | the same child as row 2 | "Already on an earlier row" |

3 matched, 3 named, 6 accounted for. The created round carried
`studentIds: [2]` and the Hindi note intact through the jsonb.

## 6. Four defects found by looking

### B-28 — "1 कक्षाओं में"

The count line read *"14 बच्चे · 1 कक्षाओं में"* — a plural Hindi noun on a
singular number. Obvious to every Hindi speaker in the school and invisible to
anybody reviewing the code in English, which is exactly why it shipped: "1
children" would have been caught in a second.

Fixed with `counted()` in `language.ts` — a function rather than two message
keys, for the reason `countOfPair()` is one: the number moves, the noun changes
with it, and a component choosing between two keys by hand is one that will
eventually only remember to do it in English.

### B-29 — a 16px link on the round builder

The phone baseline caught a 16px-tall link at the bottom of the form, the same
defect class as B-24's 20px back link. Removed rather than enlarged: the page
already has a 44px back link to the same place, and a second one too small to
tap is worse than not having it.

### B-33 — a gap filter narrowed a frozen list

Found by reviewing the resolver rather than by a failing test, because nothing
would have failed loudly. A round whose audience carries an explicit
`studentIds` list still had the house, route, search and **gap** filters applied
on top of it — so a list frozen from a gap selection, re-resolved days later
after some of those gaps had been filled in, would quietly cover a smaller set
than the list it was frozen from.

That is precisely the nondeterminism freezing exists to remove, and SamPark's
`audienceWhere` spends a paragraph on it. **A frozen list is the whole
audience**; `enrolled` still applies, because a child who has left is not
somebody to ask a teacher about whatever a list typed last term says.

The journey now builds exactly that shape — four children who all hold the
value, plus a gap filter for it — and asserts the round still covers four. It
fails without the fix, which was checked by reverting it.

### B-30 — the match report ran together as text

*"पंक्ति 4NOPE-404Somebody Missing"*. A margin separates pixels; a screen reader
and a copy-paste into the message to whoever fixes the sheet both read the
text. Real spaces now.

## 8. What this task did **not** do

- **No links.** A round has an audience, fields and a due date, and mints
  nothing. The fan-out, the recipients and the master link are R3.3. The round
  page says so in a notice rather than showing an empty list somebody reads as
  a failure.
- **House and route audiences are not offered.** The columns exist on
  `public.students` and **every one of them is empty** on schoolfees-dev — 0 of
  139 for `house`, `transport_route_id` and `village_city` — and rule 2 forbids
  writing them. The resolver handles both dimensions and there is no way to
  demonstrate a non-empty one here, so no chips are shown for a filter that
  could only ever return nobody. Recorded as **B-31**.
- **Nowhere holds house or route ownership.** `class_teachers` covers classes;
  `staff_profiles` has no equivalent, so a house or route round has no
  recipient to fan out to. That is a schema decision R3.3 has to take first.
  Recorded as **B-32**.
- The audience carries `search`; the builder does not offer a box for it yet.
- `ask_note` still has no reader on a teacher's link — `rollForRequest` carries
  it, and the screen that shows it arrives with the fan-out.
