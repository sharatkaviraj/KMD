## 1. The third reading — B-09

`smoke:roles` used to compare two things that come from the same place: the
permission each page's own `requirePermission()` names, and what
`permissions.ts` says that implies. A page asking for the wrong permission
agrees with itself, and 216 green combinations say nothing about it.

`tests/fixtures/role-expectations.ts` is a second opinion written from PLAN §3
by hand: 36 routes, each with the roles that should be able to open it and the
sentence it comes from. The runner now compares three readings and distinguishes
two kinds of disagreement:

| Disagreement | Meaning | Result |
|---|---|---|
| screen ≠ permission map | the guard names the wrong permission, or forgets | **fail** |
| permission map ≠ PLAN §3, **owned** in the expectations file | a product drift somebody has looked at | reported every run |
| permission map ≠ PLAN §3, **unowned** | a drift nobody has looked at | **fail** |

### What it found on the first run — B-22

```
216 of 216 executed · 210 as expected · 6 known drift · 0 failed

  B-22 → R1.2 — 6 cases
    view_only · /teach
    view_only · /teach/attendance
    view_only · /teach/class/[id]
    view_only · /teach/corrections
    view_only · /teach/register
    view_only · /teach/student/[id]
```

`view_only` holds `attendance:view`, and those six screens are guarded on it.
Every one is either an editable form or a list of named children, and PLAN §3
gives the viewer "Read-only information; **no editable forms or per-child
actions**". It also puts a Teach tab on a viewer's navigation bar leading to an
empty teacher workspace.

Not fixed here: it is a permission-map change and R1.2 owns the role navigation
it belongs with. It is named in code with an owner, so it cannot be absorbed
quietly, and `npm run smoke:roles -- --strict` is what R1.2 turns on when it is
resolved.

Machine-readable: `R0.3-smoke-roles-2026-09-17.json` (216 expected, 216
executed, 210 as expected, 6 drift, 0 failed; slowest case 3,687 ms).

## 2. The smoke can now fail — B-10

Three changes, each verified against the broken state before being trusted
(D-96):

| Change | Proof |
|---|---|
| A missing fixture is a failure, not a skip | `fillIds` patched to return null for `/collection/[id]`: **6 failures, exit 1**, each naming the route and saying to run `qa:seed` |
| An unowned drift is a failure | the `difference` removed from one expectation row: **1 failure**, "the permission map disagrees with PLAN §3 and nothing in role-expectations.ts owns it" |
| A short run cannot report a pass | `report.executed !== report.expected` refuses before any other verdict is printed |

Also added: a 20-second per-case deadline (a hung screen is a failed case, not a
hung run), per-role slowest-case timing, and `--json`.

## 3. Two browser journeys

`npm run smoke:workflows` — Playwright, Chromium, Pixel 7 viewport, against a
**production build** on `:3100`. The installed Next.js guide recommends exactly
this for `async` Server Components
(`node_modules/next/dist/docs/01-app/02-guides/testing/index.md`), which is most
of this app.

Deliberately **not** part of `npm run check`: it needs a database and a browser
and CI has neither. `check` is what must pass before a merge; this is what must
pass before a phase gate.

### T1 — a teacher takes her register

Signs in as the QA teacher (Hindi), and asserts the rows at every step rather
than the toast:

1. Today offers her own class under "करना बाकी", and the link goes to the register.
2. All present, then two exceptions.
3. Submit → the badge appears **and** the register row is `submitted`.
4. 15 marks, exactly 2 `absent`, 13 `present`.
5. Reload → the absence is still `aria-pressed`.
6. Submit again → same register id, still 15 marks (no duplicate).
7. Back on Today, the class is **gone** from "needs doing".

### O1 — the office asks, a teacher answers with no account

1. Office (Hindi) creates a request: class, one field, both titles.
2. The row exists, `status = draft`, token ≥ 16 chars, and the request asks for
   exactly the field that was ticked.
3. **`/r/<token>` answers 404 while the request is a draft** — the same 404 an
   invented token gets, not "closed" and not "not ready".
4. The office presses "Open the link"; the status becomes `open`.
5. In a **fresh browser context with no session**, the link loads the roster.
6. A nine-digit phone number leaves the Send button **disabled** — and no
   submission row exists. The refusal is asserted against the absence of a row,
   which is the half a message cannot tell you about.
7. A ten-digit number saves: exactly one `pending` submission with that value.
8. Re-answering **replaces** it — still one row, new value.
9. The office's review queue shows the new value.

### Teardown, and the bug in the first version of it

Both journeys restore what they touched, and the first teardown was wrong in a
way worth recording: it assumed the register was the test's own and skipped
cleanup whenever it found one already there. **A register for today already
exists** — the `open-registers` job opens one per class every morning — so the
run left Class 1 `submitted` and the next run failed with "there is nothing to
do today". The teardown now snapshots the register's columns and its marks and
puts both back.

Verified: the suite was run four times; after the fix, today's Class 1 register
is `open` with 0 marks before and after, and no `QA mother phone …` request
survives.

## 5. Limitations

- Two journeys, not a matrix. Marks, cover, imports, photos and the fee handoff
  have no browser coverage at all; R5 and R8 own those.
- No offline, storage-failure, expired-session, two-tab or >1,000-row case is
  exercised yet. The attendance queue's storage hypothesis (B-12) is still
  unreproduced.
- Chromium only, one viewport. No axe pass, no keyboard-only pass, no 200 % zoom
  — R7.2.
- The workflow suite is not in CI. It needs a dev database credential CI does
  not have, and giving CI one is a decision, not a convenience.
- **B-23 raised**: the `Section` primitive renders a bare `<section>` with an
  `<h2>` inside and no `aria-labelledby`, so every landmark on every screen is
  unnamed. Both journeys locate sections by their heading instead. R1.3 or R7.2.
