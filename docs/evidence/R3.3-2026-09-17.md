# R3.3 — one round becomes nineteen links, and says who it cannot reach

Run on 2026-09-17 on branch `r3-3-fan-out`. Baseline `4668104` (R3.2).
Verified against a production build with the R0.2 fixtures on schoolfees-dev.

## 1. What this closes

R3.2 could write a round down. It minted nothing. This is the fan-out: one
question becomes one link per group, each with its own token, its own frozen
roster and its own recipient — and the groups it *cannot* send are named
rather than quietly dropped (S-03, S-04, B-02).

## 2. B-32 first, because it blocked the rest

`vppsone.class_teachers` covered classes and nothing covered a house or a bus
route, so a house round resolved to children and then had nowhere to send them.
`vppsone.staff_scopes` is that fact, normalised: `(staff_profile_id, kind,
value, session_label)`.

**Classes deliberately stay where they are.** Merging them would mean either
dropping `class_teachers`' `role`, `effective_from`/`effective_to` and
`replaced_reason` — which exist because a class teacher is replaced mid-year
and the register has to know when — or bolting four columns that mean nothing
for a bus route onto every row. One source of truth per kind; `ownersFor()`
reads both.

Matching is **exact**. Several bus routes differ only by a parenthesised suffix
("Amet Railway Station (Inside)" against "(On Road)"), so a prefix match would
hand one route's children to another route's in-charge.

## 3. Three outcomes, none of them a guess

A link sent to the wrong teacher is a group that never gets collected and
nobody notices until the due date. So `chooseRecipient()` answers **one**,
**more than one**, or **nobody**, and the last two are the office's to resolve:

- *More than one* is a **choice for this round**, not a mistake to clean up.
  Both people really do hold it, and dropping one on the strength of a send
  would be a deletion nobody asked for.
- *Nobody* says so and offers the list.
- A teacher with **no number** blocks the group too, caught in the plan rather
  than at insert time — a link nobody can be sent is a roster frozen for
  nothing, and catching it early means the preview can offer a box to type one
  into.

## 4. Who gets left out is first class

House is recorded for about a third of a school and bus route for about half.
Grouping a house-wise send by house silently drops every child with no house on
record, and those are exactly the children whose records are thinnest: the
office believes it asked about everyone and nobody finds out.

So `unassigned` is **returned alongside** the groups, never derived from two
totals disagreeing, and both it and the blocked groups are stated in words
before anything is created.

**B-34 came out of this.** The first version labelled the skipped total *"in no
group"* — but skipped is blocked *plus* unassigned, and a child in a class
whose teacher has no number is very much in a group. Calling them ungrouped
sends the office looking in the wrong place. It reads "N children no link would
reach" now, which is the fact, and the two lists underneath say which problem
each one is.

## 5. The fan-out is not one transaction, deliberately

Per-link atomicity is kept: a link whose roster fails to freeze deletes itself,
so none ever opens to an empty list. But if link seven of eleven fails, the
first six are **kept** — six live tokens with frozen rosters are six classes
the office can send to right now, and deleting them to satisfy an
all-or-nothing aesthetic destroys real work and buys nothing, because the
office would simply do it again.

Sequential, not `Promise.all`: nineteen concurrent bursts each doing a chunked
roster insert is how a connection cap is met, and going in order means a
failure stops at a known point.

**There is no separate resume path.** A resume *is* "create the groups that are
not there yet", so it is the only path — which means the half that runs after a
failure is the same code that ran before it, rather than a second
implementation nobody exercises until something has already gone wrong. The
unique index on `(round_id, audience_kind, audience_label)` is what makes a
double-tapped button safe.

A partial run reports as one. Saying "done" over six of eleven links is how an
office finds out in a week that five classes were never asked.

## 6. Exercised in the browser, and one defect found by reading

A round over three classes chosen for three different outcomes:

| Class | Teacher | Outcome |
|---|---|---|
| Nursery (6) | has a number | link made, **6** frozen |
| JKG (4) | has a number | link made, **4** frozen |
| Class 1 (15) | no number saved | **no link**, named as held up |

Plus the office's own master link: no owner, `All classes`, **10** members —
exactly what the two class links cover between them, not the whole audience,
which would have included the class left out.

The screen said *"15 बच्चों तक कोई लिंक नहीं पहुँचेगा"* — 15 children no link
would reach — and *"रुके हुए: 1"* with "कोई शिक्षक दर्ज नहीं है" against Class 1,
before anything was created.

Then:

- pressing it **again** created nothing: still 3 links;
- the tokens answered **404** while draft — the same 404 an invented token gets;
- "turn the links on" opened all three and the round, and the same token then
  answered **200** to a browser with no session at all, rendering the roster.

`tests/e2e/fan-out.spec.ts` asserts all of that against the database, including
that the held-up class has **no link at all** — not an empty one, not one with
no recipient.

### B-36 — resume would have broken on an archived link

Found by reviewing the repo rather than by a failing test. `createLinks` worked
out which groups still needed a link from `linksForRound()`, which hides
archived ones because the board should not show them — but **the unique index
does not hide them**. It is on `(round_id, audience_kind, audience_label)` with
no `archived_at` in it, so resuming a round after archiving one of its links
would have tried to mint a second link for a scope that already had one, and
failed permanently on a round nobody could see the reason for.

Nothing archives yet, so this was a trap laid for whoever adds it. Resume now
reads every scope the round has **ever** minted — and that is the right
behaviour as well as the safe one: a scope that was archived was still asked,
and asking it again is a decision somebody takes deliberately.

## 8. What this task did **not** do

- **Nothing is sent.** VPPS One does not message a parent or a teacher (D-10,
  D-76). The board's "handed over" and "chased" are the office writing down
  what it did in WhatsApp itself, so the board reflects what happened rather
  than what this app attempted.
- **No house or route round can be demonstrated.** `staff_scopes` exists and
  the resolver handles both, but `public.students.house` and
  `transport_route_id` are empty for all 139 rows on dev and rule 2 forbids
  filling them (B-31). No screen assigns a house or route in-charge yet either.
- **No per-group override.** SamPark lets the office pick a teacher for a
  blocked group and type a number for one without. Both are recorded on the
  schema (`contact_phone`, `assigned_staff_id`) and neither has a control; the
  office fixes it in the staff record for now. Recorded as **B-35**.
- **No superseding or precedence.** Two rounds asking the same class for the
  same field make two links, and nothing reconciles them. That is R3.4.
- `reminder_count` increments and nothing reads it back except the board's own
  label.
