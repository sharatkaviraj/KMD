# R3.1 — a question asked on Monday is still Monday's question

Run on 2026-09-17 on branch `r3-1-rounds`. Baseline `55175dd` (R2.3).
Verified against a production build with the R0.2 fixtures on schoolfees-dev.

## 1. The defect, stated plainly

A request's roll and its prefilled values were re-read from `enrolments` and
`student_records` **every time the link was opened**. Two consequences, both
silent:

- a child moved between classes after a link went out stopped being on it, and
  a child moved *in* appeared on it — so the sheet a teacher was halfway
  through filling changed underneath her;
- an office correction changed what "the number we hold" meant, so the teacher
  was shown one value, confirmed it, and the review queue compared her answer
  against a different one.

Neither shows up as an error. Both look exactly like working software. That is
B-07, and S-02 is the SamPark behaviour it is missing.

## 2. What was built

`supabase/migrations/20260917122238_create_collection_rounds_and_frozen_members.sql`

| Object | What it is for |
|---|---|
| `vppsone.collection_rounds` | One round of asking: audience, fields, due date, reason, recipient mode. Its links are `collection_requests` rows carrying `round_id` |
| `collection_requests.round_id` | `ON DELETE SET NULL`, not cascade — a link outlives the round, and deleting a round must not delete answers |
| `collection_requests.audience_kind` / `audience_label` | `class`/`house`/`route`/`list`/`master` and how the group reads. `audience_label` backfilled from `class_label`, then `NOT NULL` |
| `collection_requests_class_kind_has_a_class` | `class_id` lost its `NOT NULL` so a house can span classes; this keeps a *class* request from being created without one |
| `collection_requests_round_scope_idx` | Unique on `(round_id, audience_kind, audience_label)`. This is what makes Resume safe — a double-tapped Resume hits the index instead of minting a second token |
| `collection_requests.sent_at/sent_by`, `reminded_at/reminded_by/reminder_count`, `contact_phone`, `archived_at`, `token_rotated_at` | Handing over happens once; chasing happens weekly. Deliberately different shapes |
| **`vppsone.collection_request_members`** | Who was asked and what we held, frozen at issue: `roll_no`, `snapshot jsonb`, `ask_note` |

`audience_kind` is **plain text with no enum and no check**, so a fifth kind
costs a row rather than a migration; every reader carries the value through
unchanged and an unrecognised kind reads as itself.

### The freeze

`createRequest()` now calls `freezeMembers()` after attaching the fields —
after, because the snapshot is per field, and freezing first would record a
roster with nothing in it. It resolves the roll, reads the fee columns and
`student_records` once each, and writes one member row per child with the
values **as the teacher will see them**. It upserts with `ignoreDuplicates`, so
a fan-out that failed halfway is finished by running it again and an already
frozen member keeps what it was frozen with.

`rollForRequest()` reads `collection_request_members` first. A request with no
members is one made before this existed; it falls back to deriving the roll,
because an old link rendering as an empty class is worse than a rebuilt one.

### The audience model is ported, not invented

The first version of `audience.ts` gave an audience a single `kind`, which
cannot express what the office actually means. Reading SamPark
(`src/lib/students.ts` at `830548c`, rule 4) showed the model it settled on
after the same mistake, and two things in it are load-bearing:

- **OR within a dimension, AND across them.** `{classIds: [6,7,8], houses:
  ["Rana Pratap"]}` is those three classes *and* that house. The union reading
  quietly sends to the whole school.
- **A missing filter must never widen the blast radius.** An audience with
  nothing set selects **nobody**, and `allEnrolled` is the deliberate way to
  say everybody. `parseAudience()` is tolerant in one direction only: a value
  it cannot read is dropped, and dropping narrows.

The `kind` that remains is what one *link* is scoped to — SamPark's
`GroupScope` — which is what `collection_requests.audience_kind` has always
been. Conflating the selection with the scope is what the first version did.

## 3. The proof

`tests/e2e/collection-freeze.spec.ts`, 8.7s. The journey changes the world
underneath a live link:

1. the office creates a request through the form and opens it;
2. `collection_request_members` already holds the whole roll, and the snapshot
   for the first child is exactly what the school held (`9811111111`);
3. the link loads, showing that value, with every child on it;
4. **a child is moved to another class** and **the office corrects the number**
   to `9899999999`;
5. the link is reloaded: same roster, same value, and the correction is nowhere
   on the page.

### And the control

Step 5 passing proves nothing on its own — it would pass against code that
never froze anything, because there is no assertion that the freeze is what did
the work. So step 6 **deletes the member rows and reloads the same link**. That
is not a hypothesis: it is the legacy path `rollForRequest` still takes, and it
is precisely the old behaviour.

| | Frozen | Unfrozen (the control) |
|---|---|---|
| Children on the link | all of them | one fewer — the moved child is gone |
| Value shown for the first child | `9811111111`, as issued | `9899999999`, today's |

B-07 reproduced on demand, thirty lines below the fix that closes it.

Everything the test touches is VPPS One's own — `enrolments`, `student_records`
— and both are restored in `afterAll`. Nothing writes `public.*` (rule 2), and
the numbers are invented.

## 4. Two defects found while building it

### B-26 — `/collection` threw for every role

Adding `sent_by` and `reminded_by` gave `collection_requests` **three** foreign
keys to `staff_profiles`. PostgREST then refuses the unnamed embed —
*"more than one relationship was found"* — and the whole select fails, so every
`/collection` screen rendered an error card. Named in two places:
`requests-repo.ts` and the nested one in `submissions-repo.ts`.

`tests/embeds.test.ts` exists specifically to catch this and **stayed green**,
because it read foreign keys out of `create table` blocks only. A table gains
most of its second and third references by `alter table`, which made the check
strongest on the day a table was written and blind ever after. It now reads
both, and asserts `collection_requests` is in the ambiguous set — which is also
what proves the new half of the parser runs at all.

### B-27 — a source-scanning test that passed in CI and failed locally

`tests/directory.test.ts` matched the repo's source within a 600-character
window. The file is checked out CRLF on Windows, so the same code measured
longer here than in CI: green on the runner, red on a developer's machine. It
normalises now, as `embeds.test.ts` already did.

## 5. Identity mapping (S-10)

SamPark keys students on its own text id — `S1001`, from its own imports — so
there is no arithmetic that turns `public.students.id` into one, and `apps.ts`
has never emitted a SamPark deep link.

`vppsone.external_student_ids` is the table that ends the guessing, and
`sampark.student()` now emits a detail link when **two** things hold:

1. a mapping row exists for this child, and
2. `idsTravelBetween(from, to)` — the same dataset on both sides.

Both, not either. A mapping matched on schoolfees-dev pointed at live records
would not 404; it would open a *different child*, quietly, with their name on
it. `mappingApplies()` refuses that, and two rows where there should be one are
treated as none, because a link that depends on row order will one day pick the
other one.

The path `/students/<id>` was read off SamPark's own `src/app` tree at
`830548c`, not guessed. `LINKABLE_PATHS` covers it, so the "no invented link"
test does.

**Nothing populates the table yet.** The matcher belongs with the student
source tooling in R4.1, so `externalId` is null in practice and the link still
degrades to search — the same honest behaviour as before. What changed is that
it is now a missing row rather than a missing mechanism.

## 7. What this task did **not** do

- **No round is created by any screen yet.** `collection_rounds` exists and is
  empty; the wizard that fills it is R3.2 and the fan-out that mints its links
  is R3.3. Requests made today are single-class requests that carry
  `audience_kind = 'class'` and freeze their members — which is the whole of
  B-07, and none of B-02.
- **`ask_note` is read but never written.** It arrives with the Excel ask-list
  matching in R3.2; `rollForRequest` already carries it so that screen does not
  need to change this repo again.
- **No mapping rows.** See §5.
- `reminder_count`, `archived_at` and `token_rotated_at` are columns with no
  writer. They belong to the completion board (R3.3) and are here because this
  is the additive migration, and a second one to add three columns would be
  three more chances to get `NOT NULL` backfill wrong.
