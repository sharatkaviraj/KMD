# UI build decisions

Decisions taken while building the approved design (`docs/design-handoff/`).
Each one is the option closest to the design and to `RULES.md`. Numbered UI-n
so they do not collide with `docs/DECISIONS.md` (D-n).

| # | Decision | Why |
|---|---|---|
| UI-1 | The design system lives in `src/vx/`, not `src/ui/` or `components/vx/` | `src/ui` is in `PORTED_TREES` (School Fees' kit, next-intl strings). The new kit says its strings through its own pairs, so it lives outside the ported trees and the two catalogues cannot mix. |
| UI-2 | Tokens keep the design's names (`--bg`, `--card`, `--pri` …) and are scoped to `.vx` / `.vxt`, never `:root` | Four names (`--card`, `--nav`, `--info`, `--scrim`) already exist on `:root` as HSL triplets for the ported Tailwind theme. Scoping keeps both themes working side by side while old screens are still in use. Component classes (`.card`, `.btn`, …) are scoped the same way. |
| UI-3 | Dark mode follows the existing `next-themes` `.dark` class on `<html>` | One switch for the whole app. `.dark .vx` replaces the design's `.vx.dark`. |
| UI-4 | The layout flips at 900 px of the **page's own width** (container query), and the sidebar shows from a 900 px window | PLAN A.4: "flips at 900px of the content container, not the window". On a 900–1150 px screen the sidebar collapses to icons so the page still gets desktop width. |
| UI-5 | Old screens stay reachable after their module is rebuilt | Rule: keep all business logic, server actions and RPCs. They are linked from Settings → Classic screens until retired on purpose. |
| UI-6 | Language: EN shows English, "both" shows English with Hindi under key labels, हि shows Hindi first | The design is English-first with Hindi under key labels and an EN · हि switch. The switch writes the existing `preferred_language` (en ↔ hi); "both" keeps its meaning. |
| UI-7 | Eight app roles map onto the design's five menus | admin, office and view_only use the admin menu filtered by permission; accountant and fee_collector use the accountant menu. Permissions still decide every item. |
| UI-8 | Pages are wrapped by one `VxShell` for every signed-in route | One sidebar, one bottom bar, one search palette for old and new screens alike. Old screens render in the shell's content area without the `.vx` scope, so their own theme is untouched. |
| UI-9 | Branding: "VPPS One" in the app, "Shri Veer Patta Senior Secondary School" on receipts | RULES I: keep what the repo and receipts use today (`NEXT_PUBLIC_SCHOOL_NAME`). |
| UI-10 | Two new permissions: `messages:send` (admin, office, both coordinators) and `settings:manage` (admin) | The design gives Messages and Settings their own menu items. Added to the TS map and to `vppsone.role_permissions` in one additive migration; `tests/scoped-reads.test.ts` reads both. |
| UI-11 | A nav route whose redesigned screen is not built yet redirects to the classic screen that does the job | Every nav item works from the first deploy, so nothing 404s while the phases land. Each redirect is replaced by its screen. |
| UI-12 | "See the app as" borrows the permissions of the matching real role (teacher, accountant, academic_coordinator, exam_coordinator) and is a cookie on the admin's own browser | The menu matches what that role sees; writes go through `assertNotPreviewing()` and refuse. |
| UI-13 | The legacy command palette is replaced by the vx search palette | One Ctrl K, searching this person's pages, students and receipts. |
| UI-14 | The eager-JS budget is re-measured against the redesigned shell (`docs/evidence/smoothness-redesign.json`), and re-measured as each module merges until P12 | The new shell replaces the old chrome on every route and `/login` shares its chunks; it measured 10.2% over the old baseline. The 10% guard now applies from the redesign forward, and the search palette loads lazily. The script reads each route's client-reference manifest, which in this build lists the client modules of the whole app (the `/login` manifest names the same 174 modules as `/payments`), so every new screen raises every route's figure; the final baseline is taken in P12. |
| UI-15 | Payment Desk late fee is "Take with fees" or "Waive" (with reason, payments:waive_late_fee), never "later" | The ledger settles each installment's late fee right after its fees, so a later late fee cannot be represented. |
| UI-16 | Payment Desk preview copies the ledger rule (fees first, then each row's late fee; no late fee when a payment dated on or before the due date clears the installment); the server still decides at posting | Back-dated payments show the late fee they avoid, without a second allocation engine. |
| UI-17 | Cheque no. and UPI/UTR go in `reference_number`; cheque bank and date go in remarks | No new fee columns (fee tables are never altered). |
| UI-18 | Bulk entry sends its grid as the template CSV through the existing import batch | Typed rows and uploaded files share one validation path. |
| UI-19 | Sign-in, `/apps` and "Go home" land on the design's role home (`homeForRole`: admin, office and view-only → `/`, teacher → `/teach`, accountant and fee collector → `/accounts`, academic coordinator → `/academics`, exam coordinator → `/exam-office`); a stored start screen still wins | PLAN P2 role home redirect. The legacy `homeFor` stays for the classic navigation map and its tests. |
| UI-20 | Admin Today lives at `/` inside the app group; other menus visiting `/` go to their start screen or role home | The design's admin home is `/`. |
| UI-21 | A Needs-you decision is held on the device for 6 s (Undo cancels with nothing sent), then the existing server action runs | Undo without deleting anything on the server. |
| UI-22 | Attendance summaries count only marked classes, and the mark-on-behalf panel opens with everyone present for a new register | RULES C. |
| UI-23 | "Pending today" = overdue or part-paid past due; everything else unpaid is "Not due yet"; the late fee is always its own number | RULES fee separation. |
| UI-24 | The sidebar's Needs-you badge counts the same items as `/inbox` | One source for the queue. |
| UI-25 | The academic coordinator holds `attendance:mark_on_behalf` and `attendance:correct` | The design's AcadAttendance marks a class for a teacher on leave and approves change requests ("attendance oversight"). Same rows as the office. |
| UI-26 | Calendar is shown to holders of `academics:view` | Matches the page guard; view-only and the fee desk do not get it. |
| UI-27 | The old academics hub moved to `/academics/setup` and the old calendar editor to `/calendar/days` | `/academics` and `/calendar` are the design's screens; nothing old is lost. |
| UI-28 | A holiday added on the calendar writes `academic_calendar_days`; other events go to `vppsone.calendar_events` and are cancelled, never deleted | Registers and the timetable already read the days table. |
| UI-29 | "Needs attention" is one SQL view (`vppsone.v_needs_attention`): attendance < 75%, < 33% in a subject, a drop of 15+ points, 2+ open notes | PLAN P8. |
| UI-30 | The accountant's bookkeeping (cheques, deposit slips, UPI lines, requests, counter queue, reminder pauses, report schedules) lives in append-only `vppsone.acc_*` tables | Fee rows are never edited from these screens; refunds and reversals are requests the admin decides, and the money moves through the existing fee screens. |
| UI-31 | Fee setup works on the real model: "copy last year + %" is "raise every class by %", installments are the academic-fee split plus due dates, the late fee is flat per installment, transport is each route's yearly fee | The fee engine has no per-installment percentages or stop-level transport; the review step counts the impact before publishing. |
| UI-32 | Report schedules are saved but not sent, and "send to class teachers" is Copy + a wa.me link | No paid WhatsApp sends without approval (CLAUDE.md rule 8). |
| UI-33 | Absent alerts, birthday wishes and messages about notes/plans only go into `vppsone.parent_message_queue` | Nothing sends to parents without approval (CLAUDE.md rule 8). |
| UI-34 | Attendance tap cycle is Present → Absent → Half-day → Present; a teacher can change a saved register for 30 minutes from its first submit, then asks the office | RULES C. |
| UI-35 | An offline attendance save waits in an IndexedDB outbox and is resent with the same command id | PLAN A.10; the server treats the repeat as idempotent. |
| UI-36 | Notes reuse `vppsone.notes` (new columns: tags, status open/working/done, visibility, follow-up) and the academics engineer's `support_plans`; replies, notice reads and the parent queue are new tables | One notes model shared by the teacher app, the board, Student 360 and "needs attention". |
| UI-37 | The role matrix is read live from `vppsone.role_permissions` (`my_permissions()`), falling back to the built-in map; admin is locked to everything, teachers can never hold `fees:*`, and every edit is audited through `set_role_permissions()` | PLAN A.6: one editable matrix feeding the nav, the guards and RLS. |
| UI-38 | A day close is a counted, insert-only row in `vppsone.fee_day_close_events`; a reopen is a new row; receipts posted after a close are flagged rather than blocked | Locking receipts would mean changing fee RPCs; the fee app's auto-day-close cron is untouched. |
| UI-39 | Admin reversals use the existing `reverseReceiptAdminAction`; others file a request in `vppsone.fee_desk_requests`; write-offs are requests only | Append-only money (RULES). |
| UI-40 | Call outcomes map onto the fee app's five (promised → promised_pay, visit → reached, not reachable → no_answer, asked for time → dispute, wrong number → other); promises also go in `vppsone.fee_call_promises` and kept/broken is worked out from later receipts | Reuse the fee contact log. |
| UI-41 | Families group by the fee app's family group, else the father's phone, else the child; families owing only a late fee are left off the call list and counted in a note | RULES: a late-fee-only family is not a defaulter. |
| UI-42 | Reminder batches, staff notices and parent messages are queued rows only; sending stays with the existing scheduled senders | No unapproved WhatsApp sends to parents (CLAUDE.md rule 8). |
| UI-43 | New logins use the email as username; the one-time password is shown once on screen and never sent by WhatsApp | Safer than sending credentials. |
| UI-44 | Timetable edits wait in `vppsone.timetable_changes` and publishing creates a new version through the existing draft/publish; approving leave runs the existing cover absence command per school day | Reuse the timetable and cover engines. |
| UI-45 | Admission writes reuse the fee app's create/update/archive/reinstate/link-siblings actions through FormData wrappers in `src/modules/students-fees/vx/`; enquiries, Hindi name, documents and seats live in new `vppsone` tables | Keeps one write path for students; no fee table altered. |
| UI-46 | Admission concessions come only from Fee setup policies (RTE, staff child; third child automatic, read-only); the design's "sibling 10%" is not offered | The school has no such policy; inventing one would change money. |
| UI-47 | Withdraw archives with TC number `TC/<session>/NNN`; undo is reinstate. Dues on the withdraw screen show Pending today, Not due yet and Late fee apart | RULES: never add those figures. |
| UI-48 | Promotion writes the new class and decision onto the fee promotion run's entries; held back and leaving become skip with the reason in `vppsone.promotion_marks`; apply/rollback/dues guard stay the fee module's | The old screen left Class 10 and seniors manual. |
| UI-49 | Import keeps the fee module's commit loop and after-commit dues preparation; no one-step undo for an import; duplicate students are never merged automatically | Merging children's money records is not reversible enough to automate. |
| UI-50 | Welcome message after admission is copy-only; no automatic WhatsApp | CLAUDE.md rule 8. |
| UI-51 | Sign-in stays by email; Forgot password tells the person the administrator resets it | There is no self-service reset; a fake one would mislead. |
| UI-52 | The vx update banner replaces the old update card inside the shell (store flag `prompted`); both use one shared `requestActivation()` so the reload on controllerchange still happens. Outside the shell (e.g. /login) the old card still shows | One prompt per screen, one activation rule. |
| UI-53 | Fee desk reversal/write-off requests (`vppsone.fee_desk_requests`) appear in Needs you and Today beside refund requests, linking to the receipt or the dues write-off sheet | The admin decides them where the money screen already is. |
| UI-54 | A locked class is enforced by a database trigger; only the admin unlocks; report cards are issued only for a locked class | The lock holds for both apps. |
| UI-55 | Grace marks are stored beside the mark (`exam_grace`) and shown as "+nG", never added into it; re-check changes go through save_marks as a correction with its reason | Marks stay auditable. |
| UI-56 | Marks link is one token per teacher per exam at /t/marks/<token>, opening only that teacher's class-subjects; the exam office makes, renews or revokes it; a teacher can withdraw her own submission for 10 minutes | Subject teachers only their own class-subjects. |
| UI-57 | Teacher reminders go via wa.me from the coordinator's own phone; publishing a date sheet or results only records it | No automatic WhatsApp to parents. |
| UI-58 | Moderation flags a class average that moved ±15 from the previous exam (else from the school subject average); seating alternates two classes per room; duties go to whoever has had fewest | Simple, explainable rules picked over the design's unspecified ones. |
| UI-59 | Bundle baseline re-measured after merging P9–P11; /login's manifest lists every vx client module (exam screens included), so the rise is the UI-14 superset, not /login's own payload | Re-measured at each merge per UI-14; P12 takes the final baseline. |
| UI-60 | Large text is a shell class (`vx-large`, zoom 1.125 on the content) read from `vppsone.staff_ui_preferences`; saving it revalidates the layout | Most vx sizes are inline px, so a font-size change alone would not scale them. |
| UI-61 | "See the app as" uses `vppsone.role_permissions` for the previewed role (via `effectivePermissions`), falling back to the built-in map when the matrix has no rows | A matrix change should show in the preview. |
| UI-62 | Public env vars are read by literal name in `getRequiredEnvVar` so browser clients work; the session-expired prompt can no longer break the page if its client fails. A one-tap passwordless test sign-in on the deployed app was asked for and not built: the safety review blocked it as a public sign-in bypass | The shell crashed every signed-in screen on 10 Oct; a production build against a local mock Supabase now opens every route signed in. |
| UI-63 | Keyed passwordless QA sign-in at `/login/test?key=…` (owner asked, 10 Oct): signs in only `@qa.vpps.local` accounts via a one-time magic-link token through `/auth/confirm`; off unless `QA_LOGIN_KEY` is set on the server and matches, and off whenever `VPPSONE_ENV=live` or the database is not schoolfees-dev. No button on the public sign-in page | Owner wants every role testable without passwords; the key keeps it from being an open admin door on a public URL (the owner's own account is on dev too). |
| UI-64 | Test sign-in verifies the magic-link token inside the server action and redirects to the landing page, not through `/auth/confirm` | A server action's redirect to an internal route renders it in the same request, so the token was spent server-side and the cookie never reached the browser. |
| UI-65 | An admin decides a write-off on the same sheet staff request it from; approval posts through the fee app's `closeDueAsDiscountAction` and only then marks the request approved | Money moves only through the fee action; a failed posting leaves the request under Needs you. |
| UI-66 | Withdraw, undo, class move and promotion sync `vppsone.enrolments` for the children touched; import enrols missing active children without overwriting existing rows | Registers, marks and notes read enrolments, which nothing kept in step with the fee row. Leavers are marked left, never deleted, so history stays. |
| UI-67 | Calendar notices and fee reminder batches say "saved, not sent" | Nothing reads either queue, and sending to parents needs Janmejay's word (rule 8). The wording claimed an approval screen and a sender that do not exist. |
| UI-68 | Speed pass (owner asked, 10 Oct; docs/ui/PERFORMANCE.md): Student 360 tabs are client state with `replaceState`; its reads start in one wave; phone back arrow uses history Back when the list is the screen behind; router cache `dynamic` 300 s; student rows prefetch on intent; class names and session facts cached across requests (`sharedCache`, permission checks outside) | The data was already on the page, and every extra wave was a full mobile round trip. Lists are not persisted in the browser: office PCs are shared. |
| UI-69 | Student 360's Fees tab mirrors the fee app's student page (money band and ribbon, Dues table, fee breakup, receipts) from the same rows and sums (`studentFees`) | Owner asked for the fee screens to be "very close" to the Fees app; one child must never read two ways. |
