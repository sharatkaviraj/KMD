# Decisions

Settings, not facts to re-derive. Add a row rather than arguing a point twice.
An agent that picks a default the plan left open records it here.

| # | Decision | Why |
|---|---|---|
| D-1 | VPPS One is a separate repo, Vercel project and Postgres schema from the fee app | The first attempt guarded the fee *module* but changed 45 shared platform files. A boundary enforced by structure cannot be forgotten; one enforced by review can |
| D-2 | No feature flags, no canary users, no release types, no approval gates | They existed only to protect `director@` from shared code. There is no shared code now |
| D-3 | Build on `schoolfees-dev` (`wtgxcptmucjerhufzjcf`) with test-session data; cut over to live at the end | Janmejay's call. Lets the whole app be built and used before any real data is involved |
| D-4 | Everything VPPS One owns lives in the `vppsone` schema | Makes the cutover additive-by-construction and collisions impossible |
| D-5 | Fee tables are SELECT-only, and no constraint points into `public` | A foreign key would be a write into the fee app's schema |
| D-6 | VPPS One has its own roles, not `public.users.role` | Being an accountant in the fee app says nothing about teaching |
| D-7 | Push to main through a PR the agent merges when CI is green | Keeps CI honest without adding a person-shaped wait |
| D-8 | Local folder is `Desktop\vppsone`, not `VPPS one` | npm refuses spaces and capitals in a project directory name |
| D-9 | Supabase Storage for files; Cloudflare only if storage or egress cost bites | One fewer service to run |
| D-10 | Parent-facing WhatsApp stays human-pressed | Unchanged from the original plan |
| D-11 | `office` may manage staff profiles, not just read them | PLAN §3 gives office the master data and PROGRESS 1.3 files staff under it. A profile is not an account — `user_id` is nullable and logins are created in Supabase Auth by an admin — so editing one cannot grant anybody access |
| D-12 | The root file is `src/proxy.ts`, not `middleware.ts` | Next.js 16 renamed the convention and deprecated the old name. The fee app is already on `proxy.ts`, so this matches what is running in production |
| D-13 | Writes have no RLS policy at all; server actions check the permission and then use the service-role client | Keeps "who may write" in one readable TypeScript file instead of spread across policies a role change would have to be kept in step with. The SELECT policy still governs every read |
| D-14 | Permission names are the whole platform's, not only Phase 1's | Six role lists written a phase at a time drift apart. Naming the full surface once makes the map readable as a whole, and `can()` is exhaustively tested against it |
| D-15 | `view_only` gets dashboards, not every `:view` | "Read-only dashboards" (PLAN §3) is oversight — the daily numbers and who teaches what. It stops short of per-child records: no notes, marks, documents or collection |
| D-16 | An unknown role resolves to `view_only`, never to anything higher | A role added to the `staff_role` enum before the code that understands it must not be able to arrive as an admin |
| D-17 | `short_name` immutability is a database trigger, not only a form rule | It is the timetable's join key; a rename orphans every slot that named it. A server action can be rewritten, a trigger cannot be forgotten |
| D-18 | `short_name` is unique case-insensitively | "RKS" and "rks" are the same teacher to everyone except a plain unique constraint, and a case-variant duplicate is a silently wrong timetable import |
| D-19 | Exposing the `vppsone` schema to PostgREST is a migration file, applied additively | Creating the schema is not enough — PostgREST answered `PGRST106 Invalid schema` until it was exposed. It has to be replayed at cutover like any other migration, and it appends rather than replaces so the fee app keeps `public` |
| D-20 | `getCurrentStaff()` is cached per request, not across requests | The fee app caches the profile for 60s because of its traffic; this app has a few dozen users, so a role change or a deactivation should take effect on the next navigation |
| D-21 | Signed in with no staff profile is a named state, not an error | VPPS One shares `auth.users` with the fee app, so any fee-app account can sign in here and succeed. The login page says why instead of failing blankly |
| D-22 | Migration files are named for the version the Supabase MCP recorded | The MCP assigns its own timestamp. Naming the file to match keeps the repo and the database's history in exact correspondence for the cutover replay |
| D-23 | The proxy sends signed-out visitors to `/login`, but never sends signed-in ones away from it | The proxy has a JWT, not a profile. Bouncing on the JWT loops forever against a session whose profile was deactivated, and every hop runs the page. The login page already decides this from the profile, so one authority instead of two disagreeing ones |
| D-24 | The design system is the fee app's "Ledger Calm" palette, ported to Tailwind v4 `@theme` | The same staff use both apps on the same phones. A second visual language is a second thing to learn, for no gain |
| D-25 | Signed-in screens live in the `src/app/(app)/` route group, guarded by its layout | Makes the guard structural: a new screen is protected by where its file sits, not by somebody remembering a call at the top of it |
| D-26 | Navigation is derived from `can()`, and each item carries a `ready` flag | One map for access and for navigation, so they cannot drift. `ready` exists because the phase ships over several deploys — a tab whose route has not landed is a 404 with the school's name on it. A test asserts the flag matches a real page file, in both directions |
| D-27 | Pages use `requirePermission()` (redirects); server actions use `assertPermission()` (throws) | `redirect()` works by throwing a navigation signal, which a `try/catch` inside an action would swallow — and a swallowed guard is a guard that passed |
| D-28 | A navigation bar with fewer than two tabs is not rendered | Its only job is showing where else you could go. With one tab it says nothing and costs 68px of a phone screen |
| D-29 | Staff search filters in the browser, over the whole list | A school has a few dozen staff. One fetch and instant filtering beats a round trip per keystroke, and it keeps working where the signal is worst — which is the corridor, which is where it is used |
| D-30 | A phone number that is not a 10-digit Indian mobile is refused, not stored as typed | Phase 5 messages these numbers. A wrong number that looks right is worse than a blank |
| D-31 | Staff are deactivated, never deleted | The timetable, attendance and marks all reference the profile, and `short_name` is the join key. Inactive means "not in the pickers", not "never existed" |
| D-32 | Fee-table reads go through the service-role client, after `assertPermission()` in the repository function itself | The fee app's RLS gates `public.classes` and `public.students` on `has_any_permission()`, which reads `public.users.role`. VPPS One staff have no row there (D-6), so a cookie-client read returns zero rows **and no error** — which renders as "the school has no classes". A policy would fix it and rule 2 forbids adding one to a fee table, so the guard moves into the app. It sits in the repository rather than the caller so a future call site cannot forget it |
| D-33 | The class-label editor saves one row at a time | Nineteen classes get filled in over more than one sitting. A single form with one Save at the bottom loses the lot to an interruption |
| D-34 | The academic session is derived from the fee app's class rows, not configured | There is no `public.sessions` table; the label lives on each class. Deriving it means the cutover follows the real session with no variable to remember. `VPPSONE_SESSION_LABEL` overrides it for the weeks when two sessions overlap |
| D-35 | Language is a property of the account — `hi`, `en` or `both` — not of the app | Janmejay's call. The school is not one audience: a teacher in the village reads Hindi, the office reads English. Showing everybody both made every label twice as long for every person and gave nobody the screen they wanted. Strings are written once as a pair and rendered per reader |
| D-36 | The login screen's language comes from a device cookie written at sign-in; a first-ever visit gets `both` | Signed out there is no profile to read. Bilingual is the only choice that cannot lock somebody out of the one screen they must be able to read. Ported from the fee app, which reconciles `preferred_locale` to a cookie for the same reason |
| D-37 | Dense surfaces — nav tabs, list rows, the browser tab title — lead with one language even for a `both` reader | A tab is ~70px and a title bar truncates. Two lines there is not bilingual, it is unreadable. Detail views, notices and form labels show both |
| D-38 | Validation messages cross the Zod boundary as JSON-encoded pairs | A schema is parsed in a server action, long before a component exists, so it cannot know the reader's language. JSON rather than a delimiter because a name or class label could contain any separator, and a message that splits in the wrong place is worse than one left untranslated |
| D-39 | A calendar day says *both* whether school is open and whether the timetable runs | They are not the same question. On an exam or an event day children come in and the register is taken, but no period runs. Collapsing the two would mean either an exam day with no attendance recorded, or a holiday that still expects a register |
| D-40 | Only non-ordinary days are stored; absence of a row means the weekly pattern | A year is a few dozen rows rather than 365, and adding a holiday is one insert. The weekly pattern is Sunday closed, **Saturday open** — the thing a general-purpose calendar library gets wrong for this school |
| D-41 | A class-teacher handover closes the old row on the day before the new one starts | Two open rows would mean "who is the class teacher today" has two answers. The partial unique index refuses it, and the close-then-open order means a failure leaves a class visibly empty rather than permanently blocked |
| D-42 | A calendar range is expanded to one row per day, not stored as a range | Every other screen asks about one day — "is school open on the 14th". A stored range would make that question a join, on the hottest read in Phase 3 |
| D-43 | A rebuild never deletes an enrolment whose student the fee app has lost | That child still has attendance and marks recorded here. Dropping the row would orphan history that is still true, so the consistency check reports it and a person decides |
| D-44 | Enrolments are rebuilt on a button, never on a schedule | A rebuild resolves every difference by taking the fee app's word for it. A child moved yesterday and a child moved by mistake look identical to the code and completely different to the office |
| D-45 | A class change and a roll change on the same child are one difference, not two | A child who moved class almost certainly has a new roll number. Reporting both would double-count one event and make the list look worse than it is |
| D-46 | The parser reports problems; it does not reject a sheet | Task 2.2 has to show the school what is wrong before anybody publishes. A short row still parses as far as it goes, so one bad line shows as one bad line rather than an empty screen |
| D-47 | `SHORT_SUBJECTS` is not ported | `docs/SOURCES.md` says it is applied at render time and that applying it while parsing produces labels matching no subject row. A test asserts the long spellings survive the parse |
| D-48 | The import dry run keeps going after the first unresolved name | A run that stopped at the first unknown teacher would make the school fix one, re-upload, and find the next — nineteen times |
| D-49 | Publishing archives the previous version before publishing the new one | The partial unique index allows exactly one published version per session, so the other order is refused. Closing first means a failure leaves the session briefly unpublished — visible — rather than permanently blocked |
| D-50 | `teaching_assignments` is regenerated last in a publish, and replaced wholesale | Last, so an interruption leaves stale assignments for a live timetable rather than assignments for one that is not live. Wholesale, because an assignment the new timetable does not contain must disappear, and a diff would put the rule in a second place |
| D-51 | "Who is free" takes the whole teaching roster, not the teachers on the timetable | Somebody with no periods at all is the *most* free. Deriving the roster from the timetable is exactly the bug `timetable2025` worked around with a hard-coded reserve list |
| D-52 | Every screen under `(app)` must be a nav tab or listed in `NON_NAV_SCREENS` | The `ready` flag only guards items already in the nav list, so a screen left out entirely was invisible to it — which is how `/timetable` was briefly unreachable. A test now requires one or the other |
| D-53 | Which session it is, and what a class is called, are gated on *being staff* — not on `academics:view` | A teacher has no `academics:view`; it guards the screens that *edit* master data. Gating the session label on it meant a teacher opening their own register was refused before a single mark could be read. A class is called "Class 6 A" and knowing that is not a privilege |
| D-54 | `on_behalf_of` names the teacher the office stood in for, never the person pressing the button | `taken_by` already records who pressed it. Setting both to the same person makes the two columns agree and records nothing — which is the one fact the column exists to keep |
| D-55 | The monthly register prints; there is no PDF renderer | The browser already owns the paper size, the margins, the preview and the Devanagari fonts, and on every device the school uses "print" is also "save as PDF". A server-side renderer would mean shipping all four again to produce a worse copy of the same table |
| D-56 | Fee figures appear on the student card only for `collection:view` | A teacher does not need a family's dues in order to teach, and putting them on a screen opened in a corridor invites the conversation the office should be having. Fees and late fees stay separate figures either way (D-33) |
| D-57 | The offline queue is an external store read through `useSyncExternalStore`, not component state | `localStorage` changes without React knowing and has to be read on mount. As component state that means `setState` inside an effect — a cascading render, and the lint rule that caught it was right. It also makes a second tab's writes visible for free |
| D-58 | A `Localized` pair whose halves are identical renders one line, not two | Proper nouns are most of them: a class is "Class 6 A" and a teacher is their name in either language. "Class 6 A · Class 6 A" looks broken to exactly the readers who asked to see both |
| D-59 | The Today card distinguishes three kinds of nothing — school closed, no class of your own, everything already in | A card that counts rows renders all three as an empty box, and only one of them means "you are finished". Telling a teacher they are free when they are not is the failure this screen exists to prevent |
| D-60 | Marks are not on the student card yet, and there is no placeholder for them | PLAN 3.5 names them, but the assessment tables arrive in Phase 6.1. An empty section promising marks is a promise the data cannot keep |
| D-61 | The substitution engine is ported whole, minus its `localStorage` plan store and its two hard-coded name lists | The ranking, the tiers, the weights and the min-cost flow have run this school's cover for a year and came across unchanged. What did not: `createPlanStore` (plans are rows here, so pruning is a query and invalidation is `substitution_plans.version_id`), and `DEFAULT_SHIFTS` / `RESERVE_STAFF` / `DUTY_STAFF`, which named real teachers in source — rule 6 forbids that here, and a school that cannot change its own part-time hours without a deploy is worse off anyway. They are rows in `cover_policies` (task 4.4) |
| D-62 | Any read that can exceed a thousand rows is paged through `fetchAllRows()` | PostgREST caps a response at `max-rows` — 1000 on Supabase — with **no error and no warning**. The published timetable is 1038 slots, so `listSlots()` had been returning 1000 of them since Phase 2: thirty-eight lessons missing from every timetable view and invisible to the planner. The worst shape a limit can take is the one where every caller still looks correct |
| D-63 | A role with more screens than the bar holds gets a "More" hub as its fifth tab | The cap is five, because a sixth on a 360px phone puts every tab under 60px. The old `slice(0, 5)` met the cap by dropping the sixth screen entirely, which is how `/substitutions` became unreachable for admin, office and the academic coordinator the day it was added — the same class of bug as `/timetable` shipping with no tab. A test now asserts that everything a role may open is reachable somewhere |
| D-64 | A vacancy is one per class and period; a shared block absorbs an absence, a parallel elective does not | ELGA is one activity with five teachers, so one away leaves four teaching and no cover is needed. "Biology / Maths (X / Y)" is two lessons side by side with one cohort each, so one away leaves a cohort with nobody even though somebody is standing in the same room. One vacancy per (class, period) even when both halves of a parallel cell are away: the room needs one cover teacher, and the unique index says the same |
| D-65 | Publishing a plan notifies the covering teachers in the app, on their own Today card — not by WhatsApp | A cover nobody was told about is a class nobody turns up to, so publishing has to reach the teacher. An outbound send is a different thing with a different cost and a different failure mode; the AiSensy integration arrives in Phase 5.4 and the scheduled nudges in 7.2, and until then the app is where the school already looks each morning |
| D-66 | Anything a coordinator sets by hand is pinned by construction, and a pin survives regenerating | They decided it. The reason to work the cover out again is that something changed *around* their decision, not that they want it undone — so the pinned rows are read first, everything else is cleared, and the engine is handed the pins as work already done so it never double-books against one |
| D-67 | The seed scripts load the app's own parser and engine from source, through a 15-line `@/` resolver hook | Node 24 runs TypeScript by stripping types, which is enough for modules that are logic and types and nothing else. A reimplementation in `scripts/` would be a second parser and a second engine to keep in step, and seeded data the app could never have produced is worse than no seeded data. `plan.ts` and `labels.ts` are split along that line for this reason |
